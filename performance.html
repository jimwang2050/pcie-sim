1. 有效吞吐与方向占用

B = Σᵢ Vᵢ / Δt
ρℓ = Wℓ / (Δt · Cℓ)

读以“请求方可以消费”计入，写以“目标可见”计入；本地接受、写 FIFO、链路 Ack 都不算完成。方向占用按该方向线字节单独计算，双向业务合计可以超过任一单向容量。

2. 链路容量

Cℓ = GT/s × Lanes / 8 × η
η_NFM = (128 / 130) × 可用率
η_FM  = 236 / 256            （仅 TLP 区，未扣 Flit 填充与控制开销）

串行速率先换算为字节率（GT/s ÷ 8），再扣编码与可用率。Gen6 的 236/256 只是名义 TLP 区上限，不代表整机可达带宽。

3. RC Bridge 两层能力

P_axi = W_axi / 8 × f_axi
C_bridge ≤ P_axi
预设：C_bridge = min(P_axi, GT/s × Lanes / 8)

物理 AXI 峰值描述接口能力；桥接器有效上限是产品策略，预设尽量与链路带宽对齐。Gen6 ×16：1024 bit ÷ 8 × 1 GHz = 128 GB/s，预设有效上限也是 128 GB/s；Gen4 ×8 的接口峰值 32 GB/s 高于链路 16 GB/s，预设取 16 GB/s。

4. 链路理想吞吐

Wℓ = Σ MRd 包字节 + Σ MWr 包字节 + Σ CplD 包字节
Tℓ = Wℓ / Cℓ
B_ideal = V / maxℓ Tℓ = minℓ (Cℓ · V / Wℓ)

各方向可以并行，因此取“最长方向时间”对应最小吞吐；只比较本轮有流量的方向。P2P 每跳单独算占用，但 V 不会因为经过两跳而重复计入。

5. 资源解析上界

D_r = Σ (占用数量 × 持有时间)
B_max = min_r (K_r · V / D_r)

Kr 是并行度（Tag、AXI outstanding、Credit、队列深度），Dr 是固定业务配比下该资源的累计占用。解析模型按无争用占用计算，是乐观上界，不包含实际排队。

6. 逐段递推、RTT 与 Tag

t_out(r)  = t_in(r) + Q_r + L0_r + S_r / C_r + T_turn,r
t_busy(r) = max(II_r, S_r / C_r) + T_turn,r
RTT_first = min_j(t_rx,j) − t_tx
RTT_last  = max_j(t_rx,j) − t_tx
B_tag     ≈ N_tag × 每笔 MRd 平均有效字节 / H_tag

RTT 从首跳发送侧开始串行化 MRd，到最后一片 CplD 抵达发起端邻接链路接收侧；不含发起端提交队列与最终重组。多片 Completion 取完成时刻的最小/最大值，不把并行路径相加。Posted MWr 没有事务 RTT，分别报告“提交→本地接受”和“提交→目标可见”。

计量边界

  • 采样窗为半开区间 [t₀, t₁)；跨窗包按发送时间比例计入，业务按整笔完成时刻记账。
  • 读按可消费、写按目标可见；整批吞吐从首笔提交计到末笔回收，包含启动与排空。
  • 方向独立记账；双向合计与单向占用是两个口径，不能互相替代。
  • 延迟按起点选样，分位数只统计已观察到终点的样本；未收齐的 Completion 单独计数。
  • Q（等待）与 L0（处理/传播）分开；不同资源的等待可以重叠，不能直接相加成端到端延迟。
  • P2P 每跳独立计算链路与 Credit，但业务字节 V 只计一次；经主机内存中转的路径不属于直达 P2P。
  • Gen6 只给解析预算；所有参数为示例值，未经硬件校准前不能作为合规或选型结论。
