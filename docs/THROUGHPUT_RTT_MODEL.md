# Throughput 与 RTT 计量模型

## Throughput：哪一层的字节、哪个时间窗

统一使用十进制 GB/s，即 B/ns。对同一半开采样窗 `[t0, t1)`：

| 指标 | 公式与归属 |
| --- | --- |
| 读有效吞吐 | 窗口内完成并可由请求方消费的业务读字节 ÷ `(t1 − t0)`。Host DMA 读 EP 时，本地 DDR 写回完成才计入。 |
| 写有效吞吐 | 窗口内达到模型目标可见点的业务写字节 ÷ `(t1 − t0)`。不以本地接受、进写 FIFO 或链路确认代替。 |
| 读写总吞吐 | 同窗各流的读、写有效吞吐之和。用于业务交付，可能超过单向容量；不能用它算某条线的占用。 |
| 单向链路流量 | 窗口内该方向实际串行化的模型线字节 ÷ `(t1 − t0)`。跨窗口的包按发送时间比例计入，含 TLP 头和配置的 NFM 封包开销，不含已折算进容量的编码/可用率开销。 |
| 单向链路占用 | 单向链路流量 ÷ 同向有效编码容量。P2P 每跳单独统计；中转两跳不能把同一业务字节算两次。 |
| 整批有效吞吐 | 全批交付业务字节 ÷（最后一笔回收 − 首笔提交），包含启动和排空成本；适合有限长度作业。 |

显式设置采样终点时，完成运行使用完整窗口，保留末尾空闲时间；事件超限时只用已模拟区间。没有指定终点时，完整运行默认到最后业务交付。业务按整笔完成时刻记账，短窗口会有粒度效应。稳态比较应单独设预热和采样窗，同时报告负载、已完成字节和样本数。

Gen4/5 方向预算：`C = GT/s × lanes / 8 × (128/130) × NFM 可用率`。每流通过对应方向的载荷和封包成本占用该容量；混合负载同时满足每方向链路、共享 CMN/DDR、桥、Credit 等资源约束。Gen6 计算 Flit 的 TLP 区名义预算，暂无事件统计。

**链路理想有效吞吐**：设整批业务有效字节为 `V`，方向链路 `ℓ` 需要串行化 `Wℓ` B（从该批 MRd/MWr/CplD 含头开销计算），有效线容量为 `Cℓ`。则 `Bideal = minℓ(Cℓ × V / Wℓ)`，只比较有流量的方向。双向负载可超过任一单方向容量，但同方向共享的流量必须合并；同一业务经过两个交换机链路不重复计入 `V`。

**达成率** = `100% × Bbatch / Breference`，分别对比 `Bideal` 与全资源解析上界 `Bmax`。分子使用整批有效吞吐，和参照的业务配比一致；采样窗吞吐另列，不能替代该分子。只有整批运行完成才显示达成率；短批次的启动和排空、低速率注入都会降低达成率。CLI 和 JSON 给出两项比值。

默认 Gen4 ×8、EP DMA 对主机 DDR 的 50:50 示例：每组读写业务各 512 B，合计 1024 B。去程是 24 B 的 MRd 加两个 280 B 的 MWr，共 584 B；返程是两个 276 B 的 CplD，共 552 B。去程串行化更久，故 `Bideal = (16 × 8 / 8 × 128/130 × 0.99) × 1024 / 584 ≈ 27.35 GB/s`。这是双向业务合计。页面「计算公式与计量边界」按本轮配置显示逐向拆解，JSON 为 `budget.idealDirections`。

## RTT：一笔 MRd 的链路往返

起点 `t_tx`：发起端的第一个 PCIe Link 开始串行化该 MRd（已获当跳 Credit）。终点 `t_rx`：CplD 的末字节到达发起端邻接 Link 的接收侧，即模型完成返程最后一跳串行化和传播，尚未进入发起端 Rx/重组服务。

- **首片 RTT** = 第一片 CplD 的 `t_rx − t_tx`；**末片 RTT** = 最后一片 CplD 的 `t_rx − t_tx`。按一笔 MRd 计，不按 AXI burst、DMA 描述符或 CplD 片数计。拆成多笔 MRd 时，每笔都有自己的样本。
- RTT 包含途中串行化与传播、交换机和目标控制器/内存服务、返程及相关排队和背压。发起端提交队列、首跳发送前等待和最终 Rx/重组不计入此 RTT。
- **Tag 持有** = Tag 回收 − Tag 分配。它通常还包含首跳发送前等待和发起端接收处理；计算 Tag 窗口上界使用持有时间：`B_tag ≈ Tag 数 × 每笔 MRd 平均有效字节 ÷ 平均 Tag 持有 ns`。例如 16 × 512 B ÷ 800 ns = 10.24 GB/s。
- **读端到端延迟** = 业务可消费 − 业务提交；包含 DMA/AXI 排队、多笔 MRd、最终响应或本地写回。页面「读端到端 · 首片」是从业务提交到请求方收到首片的观测值，和线上的首片 RTT 不同。
- **Posted MWr 没有事务 Completion RTT**。分别报告从提交到本地接受及到目标可见的单程延迟。DLL 或 Credit 回补时序不作为写 RTT。

RTT 以 MRd **发送起点**是否落在采样窗选样，允许 CplD 在采样窗后抵达；首片、末片和未收齐样本分别计数，分位数只取已观察到对应终点的样本。端到端延迟以业务提交、Tag 持有以 Tag 分配选样。吞吐则以**交付时间**选样。

页面报告 P50/P95/P99；CLI 提供末片 RTT P99，JSON 中每流 `readRtt` 含首末片分位数、样本数和未收齐数，另有 `tagHoldNs`。Trace 中 `mrd-tx-start` 和 `cpl-rx-end` 用 `txnId` 配对，可独立核算。

## 按拓扑计算与标定

给每一条方向链路或服务节点 `r` 定义管线/传播延迟 `L0_r`、服务带宽 `C_r`、启动间隔 `II_r`。事务/片段在该段的服务完成递推为：

```text
t_out(r) = t_in(r) + Q_r + L0_r + S_r / C_r + T_turn,r
t_busy(r) = max(II_r, S_r / C_r) + T_turn,r
RTT_first = min_j(t_rx,j) - t_tx
RTT_last  = max_j(t_rx,j) - t_tx
```

`Q_r` 是从进入队列到获得资源的等待，包含前序包、Credit 和共享资源的影响；第一跳在 `t_tx` 已准入，因此该段的发前等待不进入 RTT。控制器/AXI 用各自模型管线，链路使用线包字节加传播，目标 DDR/HBM 使用有效数据服务容量。拆分 Completion 时，各片从目标服务结束进入返程，分别递推，最后取完成时刻的最小/最大值。

整批固定配比 `V` B 时，资源占用需求 `D_r = Σ(每次占用的资源数量 × 占用时长)`，容量为 `K_r`，则 `B_max = min_r(K_r × V / D_r)`。链路线是单服务资源，用序列化占用时间；Tag、AXI outstanding、Credit 是窗口资源，用对应持有区间。解析模型用无争用的乐观占用，不以实测 RTT 直接替换 Tag 持有时间。

拓扑图在发起端首跳的发送侧标 `t₀`，返程最后一跳的接收侧标 `tCpl`。P2P 中间的 Switch 和第二条 Link 属于 RTT 路径，但不是发起端计量边界；双端流分别标定。每组链路显示单向容量，各方向显示占用，点击链路或模块可查 `L0`、容量及对应的 `K×V/D`。链路的 TX/RX 双线继续延伸到两侧 PHY → CTL → Bridge → CMN 的内部总线，用两条反向箭头表示双向通路；纯写没有 RTT 探针。

## 逐跳归因：端到端延迟构成

页面的「端到端延迟构成」把所选 MRd 的首片 RTT 拆到拓扑逐跳，使用同一次仿真的 `service` 事件与 `profile()`，不引入第二套参数：

| 列 | 来源 | 含义 |
| --- | --- | --- |
| `Q` | 当前跳 `service.atNs` − 上一跳到达时刻 | 本跳的准入等待，包含 Credit、共享资源与排队 |
| `L0` | `profile(model, node).latencyNs` | 该节点的管线/传播固定延迟 |
| 串行化 | 事件字节 ÷ 该节点对应方向的 `C_r` | `S_r / C_r`，读写分别取 `bandwidth` / `writeGBps` |
| 切换 | `durationNs − L0 − S_r/C_r` | DDR/HBM 读写转向代价 `T_turn`，正常同向为 0 |

首跳从 `mrd-tx-start` 开始，`Q` 记 0，与 RTT 定义一致；因此 `Σ(Q + L0 + 串行化 + 切换) = RTT_first`，页面用「逐跳合计」行对账。首片到末片的间隔单列为 `尾片`，所以色条总长对应 `RTT_last`。提交到 `mrd-tx-start` 的发起段（DMA/CPU、AXI、CTL、PHY）与 `cpl-rx-end` 之后的接收段单独列在「窗口外」，不计入 RTT，但可用于理解整笔业务流。

节点底部细条是仿真期间该节点服务资源的占用率（同节点 `:tx/:rx/:request/:response` 等服务池取平均），不是链路容量；链路占用仍以方向线上百分比为准。金色边框和「瓶颈」标记指向解析模型的最紧约束 `bounds[0]`，与实测占用是两套口径。不同事务的 `Q` 可以重叠，逐笔归因不能相加成系统延迟。

实机标定时，先用协商 Gen/Lane 固定线容量，使用发起端 analyzer 或控制器计数对齐 `t₀/tCpl`，再以无争用小读拟合路径总首延迟，以不同长度单在途分离串行化和固定项，用多在途与读写混合验证队列/窗口。没有节点级计数时，应只拟合端到端固定项，不能从一个 RTT 唯一分解 AXI、CMN、CTL、PHY 和内存时延。
