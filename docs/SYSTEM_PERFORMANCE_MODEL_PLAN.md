# PCIe 系统性能模型方案

日期：2026-11-18 · 状态：P0–P1 已批准；实现及边界见[交付说明](SYSTEM_PERFORMANCE_DELIVERY.md) · 基线：本地 pcie-sim v0.3.0

## 1. 模型要回答的问题

1. EP DMA 访问主机 DDR、主机访问 EP、EP 间 P2P 各走哪些资源？同一业务为什么读写不对称？
2. 当前限制是 CPU 发起、DMA 在途窗口、AXI/CHI 桥接、PCIe Tag、Credit、链路、目标内存，还是多流争用？
3. 加宽链路、增加 Tag、改变 MRRS/MPS、提高 AXI 并发或缩短响应时间，分别能改善多少？

建议采用两层模型：**解析上界**先筛查可能的瓶颈；**离散事件仿真**再计算请求切分、资源排队、背压和返程。两层共用输入。系统性能是本次新增范围；原 M3 的 JS 事件处理速度仍是工具自身的运行性能。默认结果用于架构比较；只有附上对应硬件的校准证据，才标为实测校准估算。

## 2. 拓扑与事务路径

以下 RP 为 RC 内的 Root Port；DDR 属于主机地址空间。图中 `RC.CTL` 同时包含 RP 的事务/数据链路资源，以及连接主机互连的适配逻辑；实现中把适配桥作为独立资源。双向箭头只表示可复用的物理路径，实际读请求与 Completion 分方向占用资源。

| 场景 | 请求路径 | 返回或完成条件 |
| --- | --- | --- |
| A. EP DMA → 主机 DDR | EP DMA → 本地互连/AXI → EP.CTL → EP.PHY → Link → RC.PHY → RC.CTL → 可选 SMMU/CHI 入口（如 RN-I/RN-D）→ CMN → 主机缓存/内存归属节点 → 内存控制器/DDR | MRd 的 CplD 反向回到原 EP，随后进入 DMA 消费端或落到 EP 本地内存；MWr 按主机侧指定的可见点计时。SLC 命中与确实到 DDR 分开统计。 |
| B1. CPU → EP BAR | CPU load/store → RN-F → CMN I/O 归属节点（如 HN-I）→ RC 桥/CTL → RC.PHY → Link → EP.PHY → EP.CTL → BAR 寄存器或显存窗口 | MMIO 读分别记录 CPU load 返回和链路 CplD；posted MMIO 写分别记录 CPU/桥接受与 EP 目标可见。门铃只计命令入口；后续 GPU/DMA 工作单独建模。 |
| B2. 主机 DMA → EP 显存窗口 | 主机 DMA 经平台 I/O 入口读取主机内存，再通过 CMN/RC 发起 BAR 写；反向搬运时由主机 DMA 发起 BAR 读并写回 DDR | 资源图拆成读源、可选中间缓冲、写目标，允许流水。该路径要求平台确实存在能访问该 BAR 的主机 DMA。GPU 自带 copy engine 拉取主机 DDR 属于 A，虽然应用同样称为 H2D。 |
| C1. EP A → Switch → EP B | EP A DMA/CTL/PHY → Link A → Switch ingress/fabric/egress → Link B → EP B PHY/CTL → BAR/内存 | 拓扑和 ACS 允许本地路由时绕过 RP、CMN、主机 DDR；MRd 的 CplD 按拓扑返程，各跳独立记 Credit 和链路占用。 |
| C2. EP A → Root → EP B | ACS 或平台路由要求上行时，经上行链路和支持转发的 RP/RC，再下行到 EP B；是否穿越 CMN 取决于平台配置 | 先验证同层级/跨 RP 的目标窗口、路由能力和地址映射。跨 RP/跨 RC 没有明确能力证据时返回“不支持/未确认”，不生成预测值。 |
| C3. 主机内存中转对照组 | A → 主机缓冲区 → B；每段可由不同 DMA 发起 | 单独记录两阶段以及能否流水、主机 DDR 额外流量和软件同步；不得计入直达 P2P。 |

CMN 节点名称取自 Arm CMN-700 示例，不把某种 HN/RN 分配、SMMU 位置或一致性行为设成所有平台的固定拓扑。GPU BAR 孔径、允许的读写访问与显存可见性通过平台配置显式声明。

## 3. 各节点的参数及可观测量

统一单位：时间 ns、频率 GHz、字节 B、带宽十进制 GB/s（等于 B/ns）；涉及速率或周期的字段先归一化再入模型。区分管线首延迟 `L0`、连续操作启动间隔 `II` 和字节带宽，避免用同一个数同时限制延迟和吞吐。

| 节点 / 资源 | 关键参数与建模方式 | 瓶颈证据 |
| --- | --- | --- |
| CPU / 软件 | 核数、MMIO 访问宽度、映射类型、读依赖链、最大有效并发、指令发起间隔、写合并策略、barrier/readback、提交与通知延迟；单独计入软件层 | 单次 load 延迟、发起间隔与在途数；可区分 MMIO 单线程慢和链路慢 |
| DMA / GPU copy engine | channel 数、描述符长度/预取深度、启动与回收延迟、源读和目标写的独立窗口、每通道最大在途字节、FIFO、调度、对齐与方向；记录搬运缓冲区读写依赖 | 描述符饿死、窗口满、源/目标 FIFO 占用、有效负载与小传输启动成本 |
| AXI/CHI Bridge（Host、RC、EP 可各有一个） | 数据位宽、时钟、每通道吞吐、AR/AW/W/R/B 就绪背压、burst/beats 上限、4 KiB 切分、ID 数及每 ID 在途、读写 outstanding、重排序缓冲、响应聚合、位宽转换、CDC、写合并、同 ID 排序；AXI 到 PCIe 为一对多映射，分别记录发起方 AXI ID、子 TLP 与 PCIe Tag | AR/AW 等待、W/R 阻塞、reorder buffer 高水位、拆包比例；能够定位 AXI outstanding 已满而 PCIe Tag 尚有空余 |
| CMN / 系统互连 | 源/目标节点、路由 hop、首延迟与每 hop 服务率、每向端口和共享边带宽、仲裁/QoS、I/O tracker、背景 CPU/DDR 流量；一致性路径可配置 SLC 命中、snoop 成本及 NUMA 远端链路 | 哪条边或端口争用；区分 hop 的空载代价与共享热点造成的尾延迟 |
| SMMU / 可选 ATS | 翻译位置、IOTLB 容量/命中、页大小、并发 page walk 和延迟；后续再配置 ATS 命中/失效和翻译请求流；walk 可选择真实争用内存或使用固定服务代价 | 命中/未命中延迟分布与 walk 资源等待；避免把翻译延迟归到 PHY |
| RC.CTL / EP.CTL | 独立收发队列、TLP 首处理与包率、Requester 的有效 Tag/Tracker、Cpl 重组条目和字节缓冲、MPS/MRRS/适用 RCB、边界与对齐、排序、Posted/NP/Cpl 独立队列与每跳 Credit 回补；必要时显式共享内部 FIFO | Tag/Tracker 快照、首/末片间隔、Completion 堆积、各类 credit stall 和排序 stall |
| RC.PHY / EP.PHY / 物理链路 | Tx/Rx 管线、PIPE/CDC 归属、速率/有效 Lane 数、各向串行化、传播；NFM 计编码和封包/DLL 开销；Gen6 FM 计 Flit 装箱、填充、flush 等待与 FEC 管线。可选重放、低功耗退出和降宽分别建模 | 各向线字节率、链路占用、填充率、重放字节、空闲占比；区分空链路等待发包与链路饱和 |
| Switch | 端口路由、每向端口带宽、内部 fabric 和仲裁、缓冲/头阻塞、cut-through 或 store-and-forward、ACS 路由决策 | 上联是否实际承载、各端口拥塞、跨流干扰、路由变化的成本 |
| 内存控制器 / DDR / EP DDR/HBM | 首字节延迟、读写持续带宽、每向/共享端口、队列深度和读写切换；初期用测得服务曲线，后续可加入通道/Bank/行命中与刷新。BAR MMIO 寄存器用单独服务节点 | 目标接收率、队列等待、命中/未命中、读写混合退化；比较主机 DDR 与显存各自的限制 |

**三个量不能合并为一个 queue depth。** AXI outstanding 从桥接受到最后 R beat 或 B 响应，允许一笔 AXI 拆成多个 TLP；PCIe Tag 以 Requester ID + Tag 管理，一笔 MRd 即使收到多片 CplD，也要到最后有效片或终止时才释放；PCIe Credit 是逐跳接收缓冲通行额度，按方向、类别和 Header/Data 分开，按接收端释放与回补时序恢复。Credit 恢复可早于该 MRd 的最终 Completion。保留 DMA 描述符/字节窗口和各级内部 Tracker 作为另外的资源。

## 4. 计算与归因

### 4.1 延迟定义

- 读：记录 `提交 → 接受 → 分配 Tag → MRd 发出 → 目标首/末字节 → 首片/末片 CplD 返回 → 请求方可消费`。同时报告首字节、整笔延迟以及 Tag 持有时间；Tag 在什么时刻分配由实现参数决定。
- 写：记录 `提交 → 本地接受 → 线上发送 → 目标接收 → 指定目标可见`。Posted MWr 没有 PCIe Completion；DLL 确认、AXI B、DMA 状态和远端可见性不是同一个时刻。使用 readback/fence 验证时显式配置其访问范围和排序条件；GPU 软件可见性必须使用对应的平台同步语义。
- 对每笔延迟按因果链分解为节点处理、串行化、传播、排队和资源阻塞。流水传输与重叠等待通过关键路径归因，不能把所有资源停顿直接相加。报告同时等待的原始计数，并用固定规则为图表分配互斥关键路径时间。

### 4.2 吞吐上界

对每条流 `i`、每个传输资源 `r`，约束 `Σ(B_i × A_ir) ≤ C_r`；`B_i` 是有效 B/ns，`A_ir` 是每个有效字节在该资源消耗的线字节或本地字节，`C_r` 是资源容量。包率资源单独约束 `Σ(B_i × packets_per_useful_byte_ir) ≤ packets_per_ns_r`。PCIe 两个方向分别计算，读的 MRd 和 CplD 均入账；DDR 通道、Switch fabric、桥接端口可配置共享约束。

- 固定请求大小和稳态时，读 Tag 上界 `B_tag ≈ 可用有效Tag × 每笔MRd有效字节 / 平均Tag持有ns`。估计达到目标带宽所需 Tag 时向上取整；同理为 AXI 窗口、DMA 字节窗口、各类 Credit 做独立的在途量检查。空载持有时间只能给乐观上界；仿真输出负载下持有时间和峰值在途。
- MPS 在发送路径限制 MWr/CplD 的负载，MRRS 限制每个 MRd 请求的数据量，并结合可用字节、4 KiB 边界和设备切分策略。Completion 按适用的 RCB 边界规则、MPS 和实现策略切分；RCB 不直接当成每片 CplD 的固定长度。首版支持明确列出的读写子集，并对不支持的对齐或协议特性报错。
- NFM 线容量先乘编码效率，再按方向扣除相应封包、DLLP 和有序集等预算，避免重复计费。Gen6 64 GT/s ×16 的单向名义容量为 128 GB/s；标准 256 B Flit 的 236 B TLP 区满载时约 118 GB/s，仍包含 TLP 头且未扣空填充及其他开销。首轮 Gen6 先给解析预算；后续以事件模型实现装箱和批量等待，避免把每个 TLP 向上取整为独立 Flit，也不依赖现有示意 CRC/FEC 作为真实编码器。

**算例（假设参数，非实测）**：Gen4 ×8 单向编码后约 15.75 GB/s。假设实际链路有效目标 13.5 GB/s，持续发出 512 B MRd，请求持 Tag 800 ns，则 16 个 Tag 上界只有 **10.24 GB/s**；需要至少 **22 个 Tag** 才能在这个 RTT 下接近 13.5 GB/s。把 Tag 从 16 加到 32 后，若 AXI outstanding、Completion 缓冲或 DDR 进一步限制，实际吞吐仍可能低于目标。对同一路径改跑 MWr 时，优先检查 P Credits、DMA 写缓冲以及目标写入服务率。

### 4.3 事件和实施边界

`业务操作 → 描述符/AXI burst → TLP → 链路传输单元 → 目标服务 → Completion/本地响应`。每级保留 `flowId / opId / burstId / txnId / parentId`，结合 Requester/Tag 和每跳方向关联；资源事件记录 `enqueue / grant / release / block`。队列、窗口、Credit 到达和释放主动唤醒下游，不用逐周期轮询模拟。先支持单 VC、正常 L0、可复现的默认调度；所有等待均可回溯到资源，运行需区分全量结束、待处理超限及无进展，未完成业务保留单独统计。

新增 `js/perf/`：拓扑/配置、解析、事件运行器、资源、场景、指标分层；独立于现有 `Sim` 的教学回放历史。复用已核验的协议语义、验证函数和虚拟时钟接口；当批量事件规模不适合当前数组调度时再换成同时间顺序一致的优先队列。教学视图只接收抽样或指定事务的 Trace；全量统计独立汇总。配置/结果导出带版本、实际生效能力、测量窗口、种子和参数来源。

## 5. 实验矩阵、校准与验收

### 5.1 必测工作负载：纯读、纯写、混合

对 EP DMA ↔ 主机 DDR、主机 ↔ EP BAR/显存、EP ↔ EP P2P 分别选定发起端与目标端，运行以下工况。读写均从发起端视角定义：“EP 读主机 DDR”是 EP 发 MRd，数据从 RP 流向 EP；“EP 写主机 DDR”是 EP 发 MWr，数据从 EP 流向 RP。交换发起端是另一组实验。对 B2/C3 等搬运任务，区分应用搬运方向与下层读源/写目标：应用单向拷贝仍可消耗两类资源，不把整笔 copy 当作纯 MRd 或纯 MWr。

| 工况 | 注入方式 | 重点因素与判定 |
| --- | --- | --- |
| 纯读（100:0） | 仅 MRd；单笔空载与满窗口分别测；CPU BAR 测依赖读链，DMA 扫描在途窗口 | AXI AR/R outstanding、有效 Tag 数与持有时间、MRRS/MPS、CplD 拆分与回程 Credit、目标读服务率；记录首字节与末字节延迟 |
| 纯写（0:100） | 仅 posted MWr；记录对齐、写合并与突发大小；若用 readback 做排空确认，放在采样窗口外并单列成本 | AXI AW/W/B 背压、P Header/Data Credit、MPS、写 FIFO、内存写服务率；同时报告本地接受量和目标可见量，避免把短时缓冲吸收误报为持续带宽 |
| 同发起端混合 | 按业务载荷字节注入 75:25、50:50、25:75（R:W）；先做固定比例交织，再比较成批读写；独立地址测资源争用，依赖地址单列 RAW / fence 场景 | 区分读请求与写数据共享正向链路、读数据走返程，以及 AXI/CTL 共享队列、DDR 读写切换、写排序对读尾延迟的影响 |
| 双端同时发起 | 两端各发一条流，测试 R+R、W+W、R+W；同一比例独立控制各流并发和注入速率 | 例如一端写与另一端发起的读，其写载荷与 CplD 可能竞争同一物理方向；检查共享上联、端口仲裁和流间饥饿 |

配比默认是**业务有效字节注入比**，不是请求数、线流量或完成比。配置读写各自的 I/O 大小、间隔、突发长度、在途上限、地址关系和种子；同时报告实际注入比、完成比和各向线字节。例：4 KiB 读和 256 B 写要达到有效字节 50:50，需要每 1 笔读配 16 笔写；若每类各发 1 笔，则读占约 94.1%。CPU BAR 基线使用目标允许的访问宽度和映射，不套用 DMA 的 4 KiB 业务粒度。

对照时固定拓扑、总注入速率、大小分布和采样口径，分别比较读/写 GB/s、IOPS、P50/P95/P99、队列积压、各向占用及 stall 归因；另做饱和扫描确定可持续带宽。混合模式的吞吐不由纯读/纯写结果线性插值；以两个方向的传输约束和节点共享资源共同求解。写压力下的读 P99 单列，并与同等读注入速率的纯读基线比较。若平台只有共享带宽而没有可靠的 DDR 读写切换数据，明确标出该参数为假设，输出敏感度范围。

### 5.2 实验、校准与验收

| 实验 | 因子 | 交付结果 |
| --- | --- | --- |
| 空载延迟 | CPU 单次 4/8 B MMIO；DMA 小请求/单在途；分别量首/尾、读/写、缓存命中/DDR、同交换机/经 Root | 每段可追踪时间线，含写的各完成口径 |
| 稳态吞吐 | 64 B / 256 B / 4 KiB / 大块业务；Tag/AXI/DMA 窗口独立扫描；MPS/MRRS 配置组合；Gen4/5 与 x4/x8/x16，另列 Gen6 解析预估 | GB/s、IOPS、P50/P95/P99、每方向效率、有效 Tag 需求曲线及平台期 |
| 争用和敏感度 | 双向、读写混合、CPU 与 DMA 抢 DDR、双 EP 抢上联；对 RTT、AXI 并发、Credit 周转、DDR 服务率逐项试验，补做 Tag×RTT、MRRS×Completion 缓冲二维扫描 | 热点节点、排队与背压占比、公平性、调参前后对比；饱和吞吐和固定注入下的延迟分开 |
| 校准与对照 | 先用链路配置和协议字段锁定硬约束；用单流单在途拟合路径首延迟，再用大块并发扫带宽；使用独立大小/方向/混合负载留作验证 | 参数分 `协议上限 / 假设 / IP 配置 / 实测拟合`；仅测得端到端时只拟合可辨识的组合值，节点保留区间 |

记录工作集大小与地址对齐、缓存热冷、NUMA 绑定、DMA 引擎和计时起止点。预热、采样、排空各自计数；稳态吞吐只统计窗口内交付字节，延迟按明确的请求样本集合统计并报告完成数及截断数。若有硬件，收集 Root/EP 控制器性能计数器、CMN PMU、DDR 吞吐、DMA 计数器及可取得的 PCIe analyzer Trace。可先集成 Arm `cmn-tools` 的拓扑/计数器信息；现有本地 `cocotbext-pcie` 可交叉验证事务行为，不能作为 SoC 性能标定。

最低功能验收：字节与资源守恒；末片前不得释放 Tag；AXI 先满和 Tag 先满可分别复现；Credit 耗尽能阻塞且回补后恢复；无争用的读写时间可手算；吞吐不超已定义的解析硬上界；直达 P2P 不经过 DDR，禁用路由给出理由；固定种子重复运行结果一致。实机误差门槛待拿到可复测平台后锁定，建议第一轮以独立样本的持续带宽误差 ≤10%、单流中位延迟误差 ≤15% 为校准目标；尾延迟先报告偏差与适用边界。

## 6. 建议实施顺序（审核后）

| 阶段 | 交付范围 | 退出条件 |
| --- | --- | --- |
| P0 解析模型 | 拓扑模板、参数/能力字典、Tag/AXI/链路容量预算；三类路径均提供纯读、纯写和混合配置及 CLI 对照样例 | 结果能手算对照；单位、方向和可达性校验通过；100:0 和 0:100 与各自基线一致 |
| P1 事件核心 | Gen4/5 NFM；完成 A、B1/B2、同 Switch C1；加入 AXI/CTL/PHY/DMA/目标缓冲、Tag/Cpl、逐跳 Credit 和共享资源仲裁；无能力依据的 C2 拒绝运行 | 每条支持路径验收纯读、纯写和 50:50 混合；比例扫描可复现从 Tag 限制到写 Credit、共享端口或目标服务率限制的迁移；双端并发按物理方向正确记账 |
| P2 系统扩展 | 依据平台数据启用 C2、C3、SMMU 命中/未命中、CMN 热点、DDR 服务曲线与背景流；Gen6 Flit 性能装箱 | 同组输入可比 NFM/FM；计数器到模型资源有对应关系；有实机数据时开始校准 |
| P3 展示与回归 | 本地 Performance 页面、场景/参数扫描、带宽曲线、延迟瀑布、瓶颈表、结果导出 | 三类路径及失败原因可在同页对照，原教学场景回归通过 |

建议先审批 **P0–P1**。首轮采用通用 CMN 型 RC 与同 Switch 拓扑，将控制器、桥和 DDR 的数字标为示例配置。若已有目标平台，可提供 CMN/RC IP 型号、AXI 位宽与频率、有效 Tag/Tracker、链路/MPS/MRRS、DMA 类型和测量数据，用于替换示例参数；这不是 P0–P1 的前置条件。
