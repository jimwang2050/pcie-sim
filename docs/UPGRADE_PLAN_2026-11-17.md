## 1. 目标与边界

目标是把现有 13 场景升级成“字段可核对、状态可解释、回放可复现”的浏览器 PCIe 教学实验台，保留静态部署、核心无 DOM、零浏览器运行依赖的特点。

本轮规划包含：协议准确性、模式能力约束、仿真状态与回放、流控与事务关联、现有高级场景校准、教学体验、性能和发布保障。

暂不纳入默认实施范围：周期精确仿真、完整 PCI-SIG 合规认证、真实 S 参数/IBIS-AMI、SR-IOV/CXL/TDISP、大型交换拓扑、QEMU/Renode 实时互联、真实分析仪二进制抓包导入、前端框架整体迁移。它们不能作为当前版本修复的前置条件。

### 1.1 三种模型层级

| 层级 | 要求 | UI 应说明的内容 |
| --- | --- | --- |
| 字段模型 | 选定报文/寄存器的布局、编码、访问属性有独立向量 | 支持范围、规范版本、字段来源 |
| 行为模型 | 关键条件驱动状态迁移，能够表现等待、拒绝、恢复 | 省略的计数器、超时或拓扑条件 |
| 示意模型 | 预设动画、近似 PHY/眼图或故障结果 | 明确标为示意；数值不能冒充协议编码或测量值 |

同一场景可以包含多种层级，但必须按模块分别标注。通过单元测试不能把整个项目标成“符合 PCIe 6.2”。

## 3. 对首次审核的修订

- R01/R02：保留请求头顺序、CfgRd Length、BE、Completion Byte Count 的修复方向，补充 6.2 §2.2/§2.3 的规则追溯。
- R03：6.2 §4.2.3.4.3 明确 242 B 输入生成 8 B CRC，要求与附录 K 机制一致；§4.2.3.4.4 及相关说明规定三路交织、符号级纠错。不能以“双份 CRC-32”或固定 bit 数阈值代表标准算法。
- **R06 收紧措辞**：Flit 模式也存在 InitFC/UpdateFC DLLP。6.2 §3.4.1 列出 Dedicated/Shared InitFC，§3.6.2.3 讨论 Flit 模式 DLLP 处理。真正需要修复的是 NFM 请求头/ACK/信用抽象与 Flit 标签混用、缺少 FM 承载/字段/重放规则，以及用户模式被静默覆盖。不能把“出现 DLLP”本身作为失败断言。
- R04/R05/R07–R09：复现结论保留。BERT 置信水平是产品统计策略，不能统一当成各代际的电气合规门限。
- “RCB=64 B”不意味着任何 128 B 请求都强制拆成两包；需同时满足请求地址、接收方规则、MPS 与边界约束。本项目两包案例应明确其前提。

## 4. 技术方案

### 4.1 核心与界面分层

渐进拆分，不同时重写协议模型和整个 UI。拟增加以下职责，实际文件名可在实施中按现有结构微调：

| 职责 | 拟定位置 | 内容 |
| --- | --- | --- |
| 场景能力注册 | `js/scenarios/registry.js` | 场景、合法配置、所需能力、支持层级、默认配置 |
| 模式策略 | `js/core/transport/` | NFM/FM 的报文、保护、序列号与传输事件策略 |
| 规则来源 | `js/core/protocol_refs.js` | 公开可展示的条款索引与建模边界；不包含本机路径 |
| 事务跟踪 | `js/core/transactions.js` | Requester+Tag、Completion 进度、状态与超时 |
| 状态与回放 | 先改 `sim.js` 及涉事场景 | 不可变事件、快照覆盖、稳定重放；后续再数据化调度 |
| 播放/UI 编排 | `js/ui/playback_controller.js`、`modal_controller.js` | 播放节拍、弹窗焦点、视图切换 |
| 测试向量 | `tests/fixtures/` | 规则来源、输入、独立预期、生成方法与引用版本 |

核心状态是唯一事实来源；UI 不再另存能与核心分歧的有效模式、寄存器值或错误级别。

### 4.2 模式和时间语义

- `requestedConfig` 与 `effectiveConfig` 分开；变更、降级或拒绝都提供原因。
- Gen1–5 可以在支持 Flit 的能力组合下使用 FM；不能因速率低就统一禁止。64 GT/s 必须使用 FM。
- 产品暂未实现的组合显示“本场景暂不支持”，不能显示为“协议禁止”。
- 首轮允许事务场景仅开放已验证的 NFM 组合；Gen6/低速 FM 事务能力按工作包完成后开放。原有 Gen6 训练和 Flit 场景保留为明确分级的示意，不声称标准字节编码。
- 时间分成协议/模型时间、显示映射、墙钟播放节拍。当前脚本不具备可恢复的真实时间时，标注“教学时间”，不能从 1:100 反推所有真实延迟。
- TLP 条带化时长、有序集按 Lane 复制时长、固定教学留白分别计算或标明，不共用一个字节率公式解释。

## 5. 工作包、依赖及验收

### WP00 · 冻结基线和规则清单

范围：记录应用提交、资料提交及实际引用文件 hash；保留现有 50 测试与 390 执行探针作为基线，登记可复现缺陷。建立“规则→源码→测试→场景”的追溯表。

交付：基线清单、支持范围表、待核验清单、独立黄金向量清单。依赖：无。

验收：每个 P1 缺陷有输入、当前结果、规范预期和定位。不能将旧实现的输出复制成唯一黄金向量。

### WP01 · 回退与调度可信度

范围：`sim.js`、`scheduler.js`、`flit_gen6.js`，并扫描其余场景可变闭包。先纳入全部可变协议状态并使事件载荷不可变，避免借局部修复重写所有场景。限制无效时间、过去事件和无效回调；明确队列上限退出原因。

依赖：WP00。验收：

- 22 µs→40 µs→退回→重放的 FEC 事件与初次完全一致。
- 对全部场景在所保留历史内做逐步回退/重放，比较完整状态和事件载荷；不只比较摘要或最终状态。
- 同时刻事件稳定排序；NaN/Infinity/过去时间按明确策略拒绝。
- UI 显示历史最早位置，200 步边界不伪装成完整任意回溯。

### WP02 · Non-Flit TLP 与 Completion

范围：`tlp.js`、枚举和内存场景、详情面板。修复请求头 DWORD 顺序、CfgRd Length、BE、Length 的报文类型语义、Completion Byte Count/Lower Address/Status。明确内部 DWORD 与显示/外部字节序。

依赖：WP00；集成验收依赖 WP01。验收：

- 覆盖 CfgRd0/Wr0、CfgRd1/Wr1、3DW/4DW MRd/MWr、Cpl/CplD；仅为已支持类型开放入口。
- 覆盖 1 DW、多 DW、1024 DW 的特殊编码、非法长度、载荷与 Length 不匹配、BE 和 4 KB 边界。
- 128 B/两个 64 B 的指定读案例 Byte Count=128→64；0 的 4096 B 编码不会被当作已完成。
- UR/CA/CRS 按事务适用条件校验，不把所有错误状态用于所有请求。
- 独立向量经手工字段核对和参考实现交叉核验；编解码往返只作补充。

### WP03 · 配置空间与 BAR

范围：`config.js`、`cfg_layout.js`、枚举场景。实现 8/16/32 位访问及字节使能；RO/RW/RW1C/保留位按选定寄存器定义；修复 BAR 属性位、探测、64 位高低 DWORD、地址精度和资源使能。

依赖：WP02 的配置访问语义。验收：

- 16 位 Command 写不影响 Status；Status 的 RW1C 位按写 1 清除。
- Vendor/Device ID 的普通配置写不能改变值；测试初始化使用明确内部接口。
- 64 位 Memory BAR 类型位为 64 位类型，探测和基址写保留固定位；4 KB BAR 示例低 DWORD 掩码保留类型属性。
- 超过 Number 安全范围的地址往返准确；JSON 使用十六进制字符串或高低 DWORD，不能直接序列化 BigInt。
- 本轮以 Type 0 行为为主；Type 1 布局若仍是示例，必须标注，不伪装成真实桥模型。

### WP04 · 场景能力矩阵与模式隔离

范围：registry、`link.js`、公共场景初始化、顶栏和场景说明。统一配置校验，显式声明 `nfm/fm/abstract` 能力。

依赖：WP00；与 WP02/03 集成。验收：

- 所有 13 场景均登记支持的速率、宽度、模式及原因。
- 不再静默把 Flit 改成 auto 或强制专属代际而不提示。
- 64 GT/s+Non-Flit 请求被清楚拒绝或提示改为 FM；低速 FM 的产品限制与协议能力分开。
- 合法组合检验有效配置和事件机制，非法/未支持组合检验提示与无状态残留。
- 不用“FM 中不允许 InitFC/UpdateFC”之类错误断言实现隔离。

### WP05 · 流控、事务匹配与排序基础

范围：`fc.js`、内存公共传输、事务跟踪模块。先实现 VC0 的 Header/Data 原子准入、阻塞队列和信用归还。定义 Requester+Tag 关联，避免 Completion 重复、遗漏、错误匹配。

依赖：WP01/02/04。验收：

- 任一信用不足不扣另一类信用，不产生 TX；更新后只发送一次；无负信用或重复归还。
- Ack 表示链路收到与 Completion 表示事务完成分开展示，不能在 Ack 时直接结束 MRd。
- 同 Requester 的在途 Tag 不冲突；分包累计匹配请求，错误 Tag、超时、重复包有明确结果。
- 按选定的排序规则加入生产者—消费者示例，RO/IDO 例外需单列前提，不能把动画位置当作排序规则。
- Dedicated/Shared、Scaled FC、回绕及多 VC 若未完整实现，明示边界，不用可用信用简化计数冒充标准全套状态。

### WP06 · Flit 教学模型校准（默认范围）

范围：Flit 核心、场景、面板和模型说明。清除“双份 CRC-32”和“≤2 bit 即可纠正”的规范性表述；区分 236/6/8/6 分区、DLP 字段示意、真实错误字节与预设错误结果。不得将现有 NFM TLP 字节称为 FM TLP 头。

依赖：WP01/04、参考条款。验收：

- TX CRC→FEC、RX FEC→CRC 的处理次序准确。
- 报文详情分别展示“布局示意”和“已实现校验”，示意不输出具有误导性的“标准校验通过”。
- 重传缓冲、序列号、Ack/Nak/Discard 的教学案例按选定规则说明；不是简单包数阈值判定。
- 支持“CRC 不匹配导致无效/重放”的解释，但未实现真实算法时不宣称由字节运算得出。

### WP07 · LTSSM、PHY、PM 和 BERT

范围：链路训练、PHY、环回、PM 场景及其模型说明。复核训练阶段条件、速率协商、均衡适用性、L0s/L0p/L1 子状态、D3hot/D3cold、唤醒路径；明确 PIPE P 状态不是 Base Spec L/D 状态的固定映射。

依赖：WP01/04；来源见追溯表。验收：

- 场景速率、实际链路速率与面板值一致；有序集与聚合数据速率不混算。
- 教学时间、真实参数和播放速度分开；不声称模拟真实 EQ 收敛或 COM 合规。
- BERT 零样本/未锁定/样本不足均不 PASS；分别显示观测 BER、统计上界、置信水平、目标值。
- 零错误单侧 95% 上界采用清楚说明的统计方法；非零错误也有明确区间方法与边界测试，不滥用零错误公式。
- PAM4/FBER 与低代际 BER 目标分开；图案元数据和真实 PRBS 发生器能力分开。

### WP08 · MSI、AER、DPC、ATS/PRI 现有场景复核

范围：现有模块和配置展示；先确认实际实现与 UI 宣称的差距，再按所选行为子集修复，不扩成整套 IOMMU 或 OS。

依赖：WP02/03/05。验收：

- MSI/MSI-X 的 Enable、向量范围、Function/Per-vector Mask、Pending/解除屏蔽路径均有定义；不把屏蔽一律解释为永久丢弃。
- AER Status/Mask/Severity 与计数、消息、主机通知分开；Mask 不简单等价于“错误没有发生”。
- DPC 触发、隔离、软件清状态及恢复条件逐项对照条款；重新核查当前“写 Control.Trigger=0 清除”注释与寄存器定义。
- RP PIO 按请求类型、支持能力和所选错误路径决定完成处理；不得对 Posted 请求统一生成 UR Completion。
- ATS/PRI 区分翻译、缓存命中、失效确认、缺页请求与响应；被失效项不能继续命中，非法/未支持请求按明确策略处理。
- 未纳入实现的完整寄存器和系统流程在详情列明，不把讲解图当作已实现行为。

### WP09 · UI 编排与教学工作流

范围：拆分 `main.js` 的注册、播放、弹窗和模型视图；保留现有 SVG 与原生 JS。给场景加学习目标、前置条件、关键观察点、结束结论、来源和简化边界。

依赖：WP04、核心事件格式稳定。验收：

- 初学/专家显示可切换，M1/M2 等内部里程碑移出用户场景名。
- 按层、方向、Tag/BDF、错误类型筛选；事件与状态、寄存器联动。
- 对话框初始焦点、Tab 约束、Escape、关闭返回焦点均可用。
- 1440/1024/390 px、明暗主题与键盘操作通过人工及自动检查；示意图在窄屏可阅读。

### WP10 · 性能、事件 schema 与导出分享

范围：先测基线，跳过隐藏视图，按帧合并渲染，按脏数据更新面板。必要时再做时间窗口/事件虚拟化。定义 `schemaVersion/eventId/requestId/causeId/modelTime/fidelity`，地址用无精度损失表示。

依赖：WP01/05/09。验收：

- 同一输入与 seed 导出结果一致；导入本项目版本化 JSON 后事件与选定模型状态可复现。

### WP11 · 自动检查、浏览器回归与发布

范围：Node 单元/场景测试拆分；新增浏览器开发测试依赖（拟 Playwright，不加入浏览器运行包）；GitHub Actions 检查与 Pages 发布关联。

- PR 提供条款映射、行为变化、截图或录屏、通过项及未覆盖范围。

### WP12 · 真实 FM 编码与 CRC/FEC（可选后续里程碑）

这是与 WP06 不同的工作：实现选定 FM TLP 头/OHC、DLP、跨 Flit TLP、序列号与重放，再实现真实 CRC/FEC 和字节错误注入。

前置：WP02/04/05/06；确认附录 J/K 或等效可靠参考实现、位序、生成矩阵和独立向量可获得。当前阅读目录只定位到章节引用，尚未定位附录正文，不作为默认可用资料。

验收：编码与独立向量逐字节一致；FEC 分别覆盖每组每位置单符号错误、跨组错误、同组多符号错误、CRC 字节/ECC 字节错误；不能保证纠正的情况由 CRC 检测并按规则重放。使用固定和随机 seed 测试，并检查错误误纠后的最终校验结果。跨 Flit TLP、Padding/NOP、DLP Ack/Nak/Discard、重复重放不得造成重复事务副作用。

## 6. 阶段安排、交付与工期

## 7. 测试与验收清单

| 层面 | 必须覆盖 | 判定标准 |

## 8. 改造与发布策略

1. 审核通过后先检查用户后续修改，在独立升级分支按小工作包提交；不覆盖未提交修改。
2. 每个工作包连同必要回归与文档交付，优先复用现有接口；不做无关格式化或批量改名。
3. 协议字节格式、64 位表示和事件 schema 的不兼容变化用版本号说明；原示例可迁移，未知格式拒绝并提示。
4. 保持默认 Pages 地址及原生运行方式；开发依赖用于测试，静态运行不依赖 Node/Python 服务端。
5. 预发布先与线上对照检查，再形成明确发布清单。**计划审核通过仅授权所选改造范围，是否推送/上线按用户审核意见确定；默认交付本地可验收结果。**
6. 发布使用可追踪提交或产物版本，保留上一成功部署的恢复路径，不用破坏历史的 reset/force push 回滚。
